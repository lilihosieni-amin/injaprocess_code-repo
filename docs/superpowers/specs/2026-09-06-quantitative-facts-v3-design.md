## 0. What changes, in one paragraph

The `quantify` agent no longer walks the estate and writes a delta. A deterministic CLI, `facts-plan`, reads the dumps and writes **candidates** — record templates, items, rule columns, import edges — with every mechanical field already filled, and packs them with the transcripts and attachments into **units** small enough that one Read brings the input in and one short Write takes the decisions out. Units run four at a time and are validated on return. A **reviewer** unit reads the assembled result once and removes duplicates and contradictions. `facts-plan assemble` turns skeleton plus decisions into the one delta `merge facts apply` already understands, and `facts-plan report` writes the owner's report. Identity moves from *where* a formula lives to *what* it computes, so one computation across four line tabs and two branches is one entry; mirrors become edges; a usefulness test becomes rule 0 of the classification; `statement` gets a contract and a lint. The five kinds, the envelope, the write ladder, the verbs and the UI stay.

### 2.2 Gate M, pre-filled and non-blocking

`dump-workbook --init-manifest` dumps first, then reads the same invocation's `sheets.json` and `formulas.tsv`. A row is **answerable** when its `unresolved[]` is non-empty; `confirmed` is derived — `true` exactly when `unresolved` is empty — and the manifest writer sets both together, so the two never disagree. `--init-manifest` writes a proposal into any judgement column that is empty and names that column in `unresolved[]`, whatever `confirmed` says; it never overwrites a filled column. The owner's answer at Gate M fills the column, removes it from `unresolved[]`, and flips `confirmed` when nothing is left. Proposals:

- `departments`: the department of the confirmed rows whose `dir` shares this row's first path segment when they all agree; otherwise left empty (the tree does not determine it — `…__Amar__Kanter` is cooking, `…__Amar__Anbar markazi` is warehouse, `…__Amar__Tedade Fooroosh markazi` is cashier).
- `branches`: `ChaleBagh|Chalebagh` → `chalebagh`, `Naharkhoran|NaharKhoran` → `naharkhoran`, neither → empty.
- `reference_tabs`: every tab that carries item codes, has **no formulas**, is not a mirror or ids tab, and whose header row names no date column (`تاریخ`, or `روز` alongside `ماه`/`سال`) — a definition table is keyed by a name, a nightly log by a date; the line-inventory and sales tabs carry no formulas at all, so the no-formula test alone does not separate them.

Only rows with a non-empty `unresolved` go to the model, which turns the proposal into Persian choices with a reason each, and only those reach the owner. A filled column is **never** re-proposed. Three cases of a wrongly confirmed reference tab are reconciled in place, silently, and recorded once as run-only issues (§2.3): a mirror tab (`reference_tab_is_mirror`), an ids tab (`reference_tab_is_ids`), and a tab that carries formulas beyond a single whole-tab mirror (`reference_tab_computes`, then treated as an ordinary computing tab — procurement's «مواد حساس»/«مواد عادی» are the case). None makes the row unresolved. A tab whose name matches `SheetsFileId` case-insensitively (the estate spells it `SheetsFileIDs` and `SheetsFileIds`) is always dumped to `rows.tsv`, is never a reference tab and never a record. `manifest.schema.json` gains `unresolved[]` and an optional `twin_of` (§2.3). The estate's 28 rows are all confirmed today, so the cooking run's Gate M is skipped.

### 2.3 `facts-plan build` — candidates, plan, inputs

Reads: the manifest; every dump in the estate (the library and import resolution are estate-wide; candidates are minted only for the department's own workbooks); the chosen transcripts; the `.text/*.txt` caches; `departments/{dept}/processes/*.json`; `facts/.index.json` for the reuse slice's identity columns, and `facts/{items,records}.json` for the two payload facts the slice and the lint need — an item's `data.unit` and the open row keys of the `units` record. Nothing else off the store is read, and `build` never writes to it. Writes into `{run_dir}`.

**`skeleton.json`** is `{schema_version, department, run, unit_symbols[], candidates: [{id, kind, unit, payload}], instances[], imports[], issues[]}`, where `payload` is exactly the mechanical `data` subset §2.5's right-hand column names for that kind. It is the only place the mechanical payload lives; `plan.json` carries ids only. `unit_symbols[]` is the open row keys of the `units` record at build time (the lint's exemption list). Provisional ids are `S-<kind>-<12 hex>` derived from content — a rule candidate from its output header and the department, a template from its signature, an item from `kind + marker + digits` (so `#1` and `##1` never collide) — so a rebuild over the same dumps yields the same ids. `plan.json` records the sha256 of every dump and transcript it read; `facts-plan status` reports `plan_stale` when one no longer matches; `build` refuses to overwrite a plan with any `done` unit unless `--rebuild` is given.

#### Candidates (each receives exactly one decision)

| candidate | rule |
|---|---|
| **record template** | Signature = (tab name, whitespace-folded, with a branch token stripped; the ordered list of item codes in the header row, ignoring empty cells, cells matching `Column \d+`, and un-coded trailing columns). Two tabs group into one template when their tab names are equal and their code lists are equal or one is a **non-empty** subset of the other — a tab whose header carries no code never groups with one that does; two tabs in the **same** spreadsheet never share a template; a tab confirmed as a reference tab is always its own template. A branch token inside a header cell is kept (it names a per-branch column). `instances[]` = every (spreadsheetId, sheetId, sheet, branch, hidden) in the group, keyed `<short>__s<sheetId>`; `location` = `instances[0]` in ascending instance-key order (a derived pointer the ladder skips and `apply` recomputes). `fields[]` = one per header cell that is non-empty and does not match `Column \d+`, plus the column that supplies `row_labels` even when its header cell is empty, with `key: c_<column letter, lowercase>` (provisional), `title` = the header text (or `null` for the label column — the unit mints it), `columns: {<instance key>: <letter>}` (one template may sit at different column letters in two instances — kanter and its twin are offset by two — and an instance missing the column is absent from the map; an offset is recorded as `issues[] column_offset`), `type` guessed from the sampled rows (`number` when every sampled cell parses), `constraints.enum` = the **intersection** of the instances' `validations.tsv` lists (a difference is `issues[] cross_record` naming the instances). `scope.branches` = the union of the instances' branches. A one-cell tab, a tab with no header row, a tab with no row below the header, a mirror tab and an ids tab produce no template. Row labels (§4) are used only when every instance of the template is under the dumper's row bound and every instance's label column has the same header text; otherwise the template's `applies_to` members carry no `rows[]` and the skeleton gets `row_labels_ambiguous` or `row_labels_partial` naming the instances. The rows above the header row are rendered into the unit's input as header notes (they carry the report's stated unit, «تمام وزن‌ها به کیلوگرم است»), excluding a cell that parses as a number or a Persian month name or whose column also carries a header cell; a header note that states a unit or a rule becomes the field's `unit` or the record's `statement` and is never stored raw. |

The unit may drop the candidate; it may not re-key it. |
| **item** | One per distinct code (`#N` food, `##N` ingredient) across the department's headers and BOM row labels, with the labels seen for it ordered by how many instances carry each, and every (instance, column) that carries it — rendered into the input, not stored. The unit picks the canonical `title` and lists the rest as `aliases`. Items are packed into their own units by code range. An uncoded column becomes an item only through a unit's `new`. |
| **rule column** | One candidate per **output header** (whitespace-folded) over the department's non-reference tabs, across every template and instance whose formulas write a column with that header; a candidate is minted only for a header that is non-empty, does not match `Column \d+`, does not parse as a date or a number, and retains at least one variant after the exclusions — a formula writing a column with no such header, or a header all of whose formulas are excluded, produces no candidate and one `issues[] unheaded_formula` naming the tab, column and rows (cooking's 24 date pass-throughs sit above the header row and fall here). Its `variants[]` are the distinct **shapes** of those formulas, each with the bindings that carry it; a shape is computed by the normaliser private to `build`: (a) replace the dump's escape sequences (`\n`, `\t`) with a space, then delete every whitespace character; (b) rename each `LET`-bound identifier to `v1..vn` in binding order, **keeping the original identifier as the parameter key for any literal that identifier binds** (a literal with no binding name takes the key `p<n>` in occurrence order); (c) collapse a brace array of literals to `{#}` and record its members as a parameter; (d) rewrite every reference — optional `'sheet'!`, then `(?<![A-Za-z0-9_$])\$?[A-Z]{1,3}\$?(?:N|\d{1,5})(?![A-Za-z0-9_(])`, optionally `:` and a second one — to `@`, **recording each rewritten reference as a positional parameter** whose value is `{"ref": "S-rec-…", "field": "c_<letter>"}` when it resolves to a column of a template in this run, else the locator (the guards keep `MIN(`, `ROUND(` and `CONVERT_GR_TO_KG` intact); (e) rewrite a bare `Table_*` identifier or a quoted `"Table_*"` string, wherever it appears, to `$T` and record it as a parameter; (f) rewrite every other numeric literal to `#` and record it as a parameter. `params` is therefore an object keyed by those names — `{"tolerancePerFoodGr": 5, "ref_1": {"ref": …, "field": "c_k"}}`, `{"ingredientId": 1, "table_1": {"ref": …}}` — never a positional list. Variants that call a library function whose body reads a table or a sheet range (the library computed in the same pass decides which) are grouped into one variant per (set of called functions) rather than per shape — their inlined food-id sets vary per row and are not parameters; the candidate stays one candidate, and in addition the engine mints one `issues[] hand_maintained_index` naming the tab and columns, because the same mapping lives in the BOM reference records. The candidate carries: `original` (the variants' verbatim samples joined into one body, one block per variant headed by its `applies_to` key range — one string, one `originals/` file), `output` (the header), `input_headers` (the headers its references point at), the called function names (context), and `applies_to[]` — one member per (instance, column, row range) keyed `<instance key>__<column letter, lowercase>__r<first row>` with `variant`, `range`, `params`, and, where the tab has row labels, `rows[]` of `{key: "r<row>", row, label, item}` — `item` being the ingredient code named by any formula on that row of that tab, taken from the left-most column that names one, because a row's identity is a property of the row, not of the formula being described. **Not a candidate:** a shape that is `@` or `'…'!@` (where such cells sit in a column whose other cells compute, `issues[] no_rule_applies` names the rows); a mirror tab's formula (QF-48; a tab mirroring cell by cell that is not a whole mirror gets `issues[] per_cell_mirror`); a formula whose `error` is `#REF!` or `#NUM!` (→ `broken_formula` with the kind). A formula whose `error` is `#NAME?`, `#N/A` or `Loading...` is a **normal candidate** — those mean an unbound custom function, an as-yet-unmatched lookup, or a dump taken mid-import, not a defect in the sheet; the engine attaches `issues[] cached_error` naming the kind and the range. |
| **script function** | A `.gs` function no sheet formula calls, containing arithmetic or a conditional (`getWeekDayCoefficient`, the order-quantity logic), is a rule candidate in the unit of the workbook that owns the script, with the body as `original`. #### `plan.json` — the units (immutable build output)

Grouping is fixed, not packed: one unit per **workbook group** — the set of workbooks the manifest gives the same `dir` path with the branch segment removed, plus any pair a manifest row names in `twin_of` (the estate needs it for `sokhari`/`fried` and `gozaresh_markazi`/`gozaresh_naharkhoran`); a reference workbook is its own group — one unit per **transcript chunk** (line-aligned), one or more **item** units by code range, attachments appended to the last transcript unit or forming one unit when no recording was chosen. A unit's id is a function of the artefact it covers, never of an estimate: `u-wb-<the group's lowest short>`, `u-tr-<recording>-l<first line>`, `u-items-<first code>`, and a split part is named after its axis (`u-wb-gozaresh-s<sheetId>`). Every unit satisfies **all** of: rendered `input.md` ≤ 20 K tokens (`ascii/4 + non_ascii/1.5`) and ≤ 1,800 lines of ≤ 1,900 characters; `est_tokens_out` ≤ 20 K, where `est_tokens_out = Σ` per candidate (item 120, rule 250, record 150 + 60 × fields, script 250) + a transcript chunk's `est_tokens_in × 0.4` (line count is not used: the estate's transcripts differ by more than 4× in tokens per line). A group over either bound splits along its natural sub-axis — a report book by line tab (each branch's copy of a tab stays in the same unit), a wide template by field group, items by code range, a transcript by line range — and `build` exits 2 naming a group that cannot be split under the bound. The estimator's constants are frozen in `expected.json` (§7) so a retune shows as a fixture diff, and `--rebuild` is required whenever a re-estimate would change the set of ids. Each unit records `{id, type, inputs[], candidates[], nodes[], est_tokens_in, est_tokens_out}` and nothing mutable.

**Unit state is derived from the filesystem** by `facts-plan status`: `done` when the latest `units/<u>/out.<n>.json` parses and passes `validate facts-unit`; `failed` when two parsing attempts exist and the latest does not pass; `pending` otherwise. A truncated or unparseable file is deleted by `status` and costs no attempt; only a syntactically complete output the validator refuses counts. The attempt count is the number of parsing `out.<n>.json` files.

#### `units/<u>/input.md`

The unit's candidates rendered compactly (a rule column as `S-r-… · «انحراف» · 1 variant · MINUS(@,@) · 60 bindings: پیتزا/فرنگی/سوخاری/کانتر × چاله‌باغ/ناهارخوران · params: —`; a template as its tab name, instances, fields with column letters and sampled types, header notes, row labels; an item as its code and labels), the transcript chunk or attachment text verbatim, the context items, the reuse slice, the process-index slice, and the expression card and style card in full (§2.4).

Estimate for cooking with all eight recordings (what `build` printed on the frozen dumps): ~26 units — the two report books 1 (they fit one unit together), each of the four line-inventory pairs 1, BOM 1 (the binding one, ~19 K rendered input), the two `ashpazkhne` books 1, items 1, transcript chunks ~17 — in seven batches. The count is what `build` prints; nothing in this document is a target.

### 2.4 The `quantify` agent, v3

Modes: `manifest` (rows with `unresolved` only), `unit`, `review`, `targeted` (`edit-fact`, unchanged in shape, with the style card). `full` is withdrawn. **`tools: Read, Write`.** The unit reads exactly two files — its `input.md` and the schema — and writes exactly one; it never reads a dump, a transcript, the store or the index; anything it needs and cannot find in its input is a `drop` with `reason_code: insufficient_context`, never a search. The prompt is: the unit contract (§2.5), the **expression card** (the FEEL keyword set, the identifier-declaration rule, the aggregate form, `key` never `name` on every member, the minted-segment grammar — transcribed from `engine/merge_facts/content.py`, with a test that the card and the checker agree), the style card (§5.2), the usefulness test (§5.1), the classification table (§5.3), the reuse rule, and the non-negotiables (no fabrication, roles not names, ASCII keys, never mints an id, cites only ids its input printed). The nine walk obligations are gone. Every dispatch carries the sentence «nothing runs in the background and no monitor exists; the results arrive as tool results in this same turn».

**`unit` mode input:** `input.md`, `schema_path`, `run_dir`, `unit`, `attempt`, and on a retry the previous `out.<n>.json` and the grouped errors. **Output:** `units/<u>/out.<attempt>.json` — always a new path — then one line («بخش u-wb-gozaresh: ۱۸ نگه‌داشته، ۷ کنار گذاشته، ۳ جدید») that the coordinator neither quotes nor relays. A retry re-emits the whole file; at this size that is expected and affordable.

**`review` mode input:** `review/input.md`, the same schema. **Output:** `review/out.json`, a `facts-unit` document with `unit: "review"` (§2.6).

### 2.5 `facts-unit.schema.json` — the unit's contract (closed)

```
{ "schema_version": 1, "unit": "u-wb-gozaresh", "attempt": 1,
  "decisions": [
    { "skeleton": "S-r-…", "action": "keep",
      "key": "enheraf", "title": "انحراف مصرف", "statement": "…", "aliases": ["مغایرت"]?,
      "data": { … the per-kind subset below; a value the unit inferred rather than read is written {"value": …, "inferred": true} wherever it sits … },
      "branches": ["chalebagh"]?,                       // only when the source names a branch
      "processes": [{"process": "cooking-030", "node": "n016", "quote": "…"}]? },
    { "skeleton": "S-r-…", "action": "drop",       "reason_code": "date_passthrough", "reason": "…"? },
    { "skeleton": "S-i-…", "action": "merge_into", "into": "S-i-…", "reason_code": "duplicate" },
    { "skeleton": "S-r-…", "action": "split",
      "into": [{ "key", "title", "statement", "data", "takes": ["<applies_to keys | instance keys>"] }, …],
      "reason_code": "other", "reason": "variants compute different things" } ],
  "new": [ <envelope entries as in facts-delta, without id; refs are {"ref":"S-…"} (a candidate of this run) or {"ref":"F-…"} (an id the reuse slice printed)> ] }
```

- A decision addresses its subject as `skeleton` (a unit) or `entry: {kind, key, scope}` (the review). Every candidate in the unit's `plan.json` list appears in `decisions` exactly once — `validate facts-unit` checks it for a document whose `unit` is a plan unit; `key`, `title`, `statement` are required on `keep` and on each `split` part. `reason_code` is from the closed set `not_a_fact | date_passthrough | cosmetic | duplicate | has_a_home | insufficient_context | other`; `reason` is optional internal text — never linted, never shown to the owner.
- Envelope fields (`key`, `title`, `statement`, `aliases`, `processes`, `branches`) are siblings of `data`, never members of it. Assemble strips every `{"value", "inferred"}` wrapper and writes the `field_status` path itself; the model never types a path.
- `processes[]` names a process id, a node id and a quote; assemble writes the file path and the process-type `source[]` entry (v2 QF-8). A node id not in the department's index is an error.
- A rule always references a template field by its **provisional** key (`{"ref": "S-rec-…", "field": "c_h"}`); a record decision renames fields as `{from: "c_h", key: "masraf_elami", …}`; assemble rewrites every edge through the rename map (§2.6). A field the record unit leaves unrenamed keeps `c_h`.
- A `split` is for variants that compute different things; it must assign every `applies_to` member and instance of the source candidate to exactly one part; parts may carry `template_of` + `divergence`. A per-binding difference in a value or in which column is multiplied is a parameter, never a `split`.

The per-kind `data` subset a decision may carry:

| kind | the unit decides | the engine already wrote |
|---|---|---|
| record (sheet) | `role` (log \| reference \| report \| config), `grain`, `cadence`, `day_boundary`, `filled_by`, `approved_by`, `movement`, `reconciled_against[]`, and per field `{from, key, unit, type, description, refItems, derived}` — `unit` only on a field whose `type` is `number` (the engine writes no `unit` key on other types and creates no unknown leaf); `primaryKey` only on a non-reference record | `medium`, `location`, `instances[]`, `fields[].title/columns`, `constraints.enum`, `rows[]`, `primaryKey` (reference), `imports[]`, `issues[]` |
| record (`new`, no dump: paper, external, native) | the whole v2 §7 payload — `medium`, `location`, `fields[]`, `header_fields[]`, `sections[]`, `rows[]`, `signatures[]`, `blank_master`, plus the sheet list above | — |
| item | `category`, `unit`, `unit_raw`, `units[]`, `pack`, `tracked[]`, `group`, `state`, `grade`, `code_absent` | `code`, sources |
| rule | `expr` + `lang`, or `table`, or `lang: text`; `inputs[]`/`outputs[]` members (`key`, `title`, `unit`, `nature`, `per`, `of`; `from`/`writes_to` as `{"ref": "S-rec-…", "field": "c_h"}`, or `from: {"param": "<params key>"}` for a value or column bound per `applies_to` member), `calls[]`, `value`/`range` on a constant, `edge_cases[]`, `template_of`, `divergence` | `original`, `applies_to[]` (with `variant`, `params`, `rows[]`), sources |
| measurement (`new` only) | `of`, `quantity` (the kind of quantity), `unit`, `method`, `when`, `by`, `writes_to`, `exceptions` — `writes_to`, or both `by` and `when`, required | — |
| note (`new` only) | `about[]` (≥ 1 ref), `question` | key (from both) |

**A rule column whose bindings carry a varying literal or basis** (the tolerances 5 / 140 / 4 / 75 / 100; per unit sold multiplying column K on some rows, per kilogram consumed multiplying column I on others) is one rule whose expression reads the parameters — `enheraf_ba_tolerance = enheraf - tolerance_gr / 1000 * basis` — with `inputs[]` carrying `{key: "tolerance_gr", from: {"param": "tolerancePerFoodGr"}}` and `{key: "basis", from: {"param": "ref_1"}}`, the values and column references already in `applies_to[].params` (the basis is the column reference step (d) recorded; two such bindings may sit in two `variants[]`, and the parameter, not the variant, is what the expression reads). Nothing ever produces one rule per line, and no constant entry is minted for a parameter; `gate-b.md` lists a rule's **numeric** parameter values from `applies_to[].params`, and renders a parameter whose value is a table name or a `{ref}` as the referenced record's Persian title or omits it.

### 2.6 Digest, review, assemble

**`facts-plan digest --run`** runs steps 1–7 in memory, discards the temp ids, and writes `review/input.md` and `review/input.sha256`. **`facts-plan assemble --run [--review]`** runs step 0 (the review, when `--review` is given and its recorded digest hash matches — otherwise the review is discarded and `assembly.json` records `review_status: discarded`) and then steps 1–9 **once** over the merged decision set, writing `facts-delta.json`, `assembly.json` `{dropped[], undecided[], provenance{}, review_status}` and `gate-b.md`. Both are deterministic; units are applied in ascending unit id. Steps are numbered in `assemble`'s execution order.

0. **Review fold-in.** The reviewer's document is a `facts-unit` whose decisions address assembled entries as `entry: {kind, key, scope}` (an address matching zero or more than one entry discards the review) with the same actions (`keep` carrying a rewritten `title`/`statement`, `drop`, `merge_into`, `split`) plus `contradiction {field, resolution: account | fix, value?, reason}` — legal only in a `review` document, `fix` only when one side is a demonstrable slip the reviewer names; a `keep` addressing a dropped candidate's skeleton id reinstates it. At most 60 decisions and 20 rewrites; `digest` prints both caps in `review/input.md` and `validate facts-unit` refuses a document that exceeds them. The review's decisions are applied onto the units' decisions; everything below runs once over the result.
1. **Temp ids** `T-1…` are minted in kind order over every entry the steps below will emit, after the review has been folded in, so every entry the delta carries has exactly one; `provenance` maps each to its unit.
   1a. **Ref resolution.** Every `{ref}` object anywhere in the assembled entries — a decision's `inputs[]/outputs[]` edges, `applies_to[].record`, an `applies_to[].params` value of that shape, `instances[].imports[].source`, and everything inside `new[]` — has an `S-` ref replaced by the temp id of that candidate's kept entry and an `F-` ref checked against the store. An `S-` ref naming a dropped candidate, or a candidate in a `failed` unit, is an error naming both units; an `imports[].source` whose `S-` target was dropped falls back to the locator.
   1b. **Field identity.** Every `{ref, field}` edge, every `applies_to[].record.field` and every `params` value of that shape whose field is provisional is rewritten to the key the owning record decision minted; a provisional key no decision declares is an error naming both units.
2. **Keep** → envelope from the skeleton (kind; `source[]` from every binding and instance, plus the process-type sources from `processes[]`; `scope` per §3.2; `retired: false`) plus the decision's fields; `inferred` wrappers expanded to `field_status`; mechanical `data` merged under the unit's.
3. **merge_into** → the target gains the candidate's bindings, instances and sources. Targets resolve to a fixpoint in ascending (unit id, skeleton id); a cycle, a dropped target, or a target in a `failed` unit is an error naming both units.
4. **split** → one entry per part with the assigned bindings; the parts are linked as the decision says.
5. **drop** → `dropped[]` `{skeleton, kind, label, reason_code, unit}`. A candidate of a `failed` unit → `undecided[]` `{skeleton, kind, label, unit}`, never `dropped[]`.
6. **new** → refs already resolved by 1a. A note's key is minted here from the sorted `(kind, key)` pairs of its `about[]` targets and the normalised question — stable across runs and across temp-id renumbering. An engine issue attached to a kept entry is written with `affects: [{ref}]` and its templated `description`.
7. **Cross-unit**: two `keep`s minting the same `(kind, key, scope)` are merged; the surviving prose is the lowest unit's and the discarded wording is flagged; a differing scalar between two decisions citing **different source kinds or speakers** becomes two accounts — each with `field` = the QF-7 path of the leaf, `status: "open"`, `speaker_role: null`, a Persian `statement` assemble writes, and `source` = the citation of the decision that supplied that side (a path under `data-repo/`, because `apply` checks account sources like `source[]`); no `id` — `apply` mints it. A differing scalar between two decisions citing the same artefact is flagged as `unit_drift`. The flags: `duplicate_title`, `two_writers` (two rules whose `applies_to` bindings overlap on an instance, column and row range), `note_overlap`, `equal_expr` (same normalised `expr` in one scope), `duplicate_code`, `edge_disagreement` — these six are members of `merge_facts.audit.AUDIT_CHECKS` that read nothing off disk, called over a store-shaped view (`load_store` plus the assembled entries, which is why step 1 mints ids first), and the audit reports them under the same six names, so `assemble` and `audit` cannot drift; `unit_drift`, `template_split` (two units minting the same instance under different keys) and `wrapper_variants` (one candidate whose variants differ only by a unit wrapper such as `CONVERT_GR_TO_KG` or an aggregation wrapper such as `SUM`) are run-scoped and live in `assemble` alone. Flags are rendered into `review/input.md`, not stored separately.
8. **Lint**: the §5.2 lint runs over every prose field and refuses (exit 2, naming the unit) rather than storing a failing value.
9. **Write** `facts-delta.json`, `assembly.json`, `gate-b.md`.

**`review/input.md`**: one line per assembled entry (`kind · key · scope · title · statement · rule: expr, input keys → output key · record: field keys with units · item: code, unit, category`), the flags, and the dropped candidates' rendered skeleton lines with their reason codes. Ceiling 50 K tokens; above it `digest` stops with the count, the run proceeds without the review, and the report says so.

### 2.7 Gate B and the report

`assemble` writes **`gate-b.md`** and `facts-plan report --run` writes **`report.md`** — finished Persian messages; the playbook sends each verbatim and composes nothing. Both name an entry by its Persian title and, after apply, its panel id; neither carries a command, an account id, a path, a unit id or a code. `report` renders `reason_code`s from one Persian table.

```
خلاصهٔ اعداد آشپزخانه — برای تأیید

ثبت می‌شود: ۱۸ قاعده، ۹ جدول، ۹۶ قلم، ۴ اندازه‌گیری، ۳ یادداشت.
کنار گذاشته شد: ۱۳۱ مورد (کپی جدول‌ها، رنگ‌بندی، خواندن تاریخ، …) — فهرست کامل در گزارش پایان اجرا.
بررسی‌نشده: ۰ مورد.

قاعده‌ها:
  • مصرف اعلامی لاین = موجودی اول شب + دریافت از انبار − موجودی آخر شب
  • انحراف مصرف = مصرف واقعی − مصرف اعلامی
  • انحراف با تلورانس: ۵ گرم به ازای هر پرس پیتزا، ۱۴۰ گرم به ازای هر کیلو مرغ، …
  … (۱۵ مورد دیگر)

اختلاف بین دو منبع: ۲ مورد (در پنل هم قابل تعیین تکلیف است)
  ۱ — مقدار قارچ در «اینجاباکس»: الف) ۲۱۵ گرم (نسخهٔ غذا)  ب) ۱۰ عدد (سرپرست آشپزخانه)

ایرادهای یافته‌شده در فایل‌ها: ۱۴ مورد (ستون‌های جاافتاده در جدول‌های کپی‌شده، یک فرمول خراب) — سه مورد مهم: …
بی‌پاسخ: واحد ۷ قلم و ۳ ستون — در پنل.
```

Approval applies the delta with disputes open; the owner answers a dispute now («۱ الف») or later in the panel. No other question is put to the owner at Gate B. A run with undecided candidates may be approved; the report names what is missing. `report.md` carries: each open dispute lettered; unknown units grouped per item; the dropped list by reason in the owner's words; every engine-computed issue grouped by kind with the record named; any skipped workbook or unfinished part («یک بخش از فایل گزارش ناتمام ماند و در اجرای بعدی تکمیل می‌شود»); whether the review ran.

## 3. The data model changes

### 3.1 Keys (v2 QF-32 amended)

| entry | key |
|---|---|
| rule from a sheet formula | a concept key minted by the unit (`masraf_elami`, `enheraf`, `enheraf_ba_tolerance`); unique within (kind, scope); the workbook and column live in `applies_to[]`, never in the key |
| record template | a concept key minted by the unit (`mojudi_avval_shab_pitza`, `gozaresh_shabane_pitza`) |
| record instance | `<short>__s<sheetId>` (engine; `sheetId` is in `sheets.json` and drift is already reported) |
| `applies_to` member | `<instance key>__<column letter, lowercase>__r<first row of the range>` (engine; never renamed); its `rows[]` members `r<row>` |
| note | `note_` + the first 12 hex of `sha256(sorted (kind, key) pairs of about[] targets ‖ normalised question)` (engine, at assemble) |
| measurement | `{item}__{record}__{column}` derived by `merge` from `writes_to`; with no `writes_to`, `{item}__{by}__{when}` |
| everything else | as v2 |

No constant is minted for a formula literal; a literal is a parameter (§2.5). `applies_to[]`, `instances[]`, `imports[]` and `applies_to[].rows[]` are ordinary keyed collections under v2 §11 — a member the store lacks is appended (a later run over another instance extends a rule instead of minting a second one); a member whose `range` or `params` changed disputes that leaf, as QF-2 requires. Members are never removed automatically; `audit` reports a member whose binding no longer exists in the dump (`binding_gone`).

### 3.2 Scope (v2 QF-43 amended)

A sheet-derived entry's `scope.branches` is the union of its instances' branches. A transcript-derived decision or `new` entry takes, in one non-transitive pass, the union of the scopes of the entries it attaches to (`of`, `writes_to`, `about`, `tracked[].record`), restricted to the run's department — an attachment resolving outside the department is an error naming the unit; attached to nothing, or only to unattached entries, it is department-wide (both branches) unless the decision carries `branches` (written only when the speaker named a branch). A workbook stub (v2 QF-20 case 2, kept) is scoped to the department of the run that mints it and to no branch; when the workbook is later read, the real record's scope replaces it through `find_match` on the instance. `scope.departments` is unchanged. The natural key stays `(kind, key, canonical(scope))`; `find_match` tries instance identity first over every instance, then the natural key. An instance match whose natural key disagrees is **not** a match: `digest` reports it as `template_split` for the reviewer, and `apply` never renames. An `imports[].source` locator is resolved at read time by the same instance identity; `edit-fact` promotes it to a `{ref}` when someone cares.

### 3.3 Payload vocabulary (closed)

`facts.schema.json` and `facts-delta.schema.json` move to `schema_version: 2` (the marker is bumped in the six committed store files in the same commit as the schema change; there is no migration verb — the store is one seed entry when v3 starts, and every later write goes through `save_store`, which validates): every `data` payload gets `properties` and `additionalProperties: false`; the enums v2 §7 declares in prose become schema enums (`item.category`, `item.state`, `record.medium`, `record.role` without `mirror`, `record.cadence`, `fields[].type`, `measurement.quantity`, `outputs[].nature`, `rule.lang`, `divergence`). Declared for the first time: `template_of` (`{ref}`) and `divergence` on rule and record; `record.reconciled_against[]` (v2 §9 shape); `record.stub`, `record.grain: "workbook"` (workbook stubs only); `rule.original` (a string in the delta) and `original_ref` (a path string, store only — the delta still forbids it; neither is an array); a row object's reserved members `key` (minted key, not a segment), `title`, `unit`, `unit_raw`, `section`, `when`, `open`, `retired`, `valid_to`, `supersedes` with their own types, then `patternProperties` on the minted-segment grammar for the cells. New members: `record.instances[]` (`{key, spreadsheetId, sheetId, sheet, branch, hidden, imports[]?}`), `instances[].imports[]` (`{key, source: {ref} | {spreadsheetId, sheet}, range, named_range?}`), `fields[].columns` (`{<instance key>: <letter>}`), `rule.applies_to[]` (`{key, record: {ref, field}, variant, range, params: {…}, rows[]?}`), `inputs[].from: {"param": …}`, `note.about[]` + `note.question` (both required), `issues[].instance`, and `issue.kind` gains `hand_maintained_index`, `no_rule_applies`, `broken_formula`, `cached_error`, `leading_offset`, `unused_mirror`, `unknown_source`, `column_offset`, `per_cell_mirror`, `ambiguous_row_header`, `binding_gone`. Removed: `record.mirror_of`, `role: mirror`, `record.foreignKeys` (replaced by `imports[]` and `fields[].refItems`; `merge facts repair-foreign-keys` is retired with it), `rule.port` and library `edge_cases[]` (they stay on a `gs` rule that is business logic). `source[].quote` is admitted for `voice`, `comment` and `sheet` sources as well as `process`. Identifier grammars: `fields[].key`, `inputs[]/outputs[].key` and row cell names take the minted-**segment** pattern; `instances[].key`, `applies_to[].key`, `imports[].key` and `applies_to[].rows[].key` take the minted-**key** pattern (all four are minted keys, not segments: the first three carry `__` by construction and `rows[].key` is a single segment the key grammar also admits); a non-ASCII homoglyph fails both.

### 3.4 The function library

`facts-plan build` computes, over every dump in the estate, one section per distinct function body (named functions from `names.tsv`, script functions from the `.gs` files; bodies compared with whitespace folded): name, kind, definers, the formulas that call it, the verbatim body. It is written to `{run_dir}/functions.md`; run directories are committed, so the latest one is the estate's reference. A FEEL expression never calls a library function — it states the business computation (an aggregate over the BOM record, not the sheet's lookup chain). No fact entry exists for a plumbing function; v2 QF-12's port list is withdrawn; `attachments/sheets/NAMED_FUNCTIONS.md` is deleted.

## 5. Rules the model applies

### 5.1 The usefulness test (rule 0 of v2 §8)

Each test names its disqualifying answer; evaluate in order and stop at the first that holds. U1 and U2 apply to rule, measurement and note candidates and to every `new` entry; a record-template or item candidate starts at U3.

- **U1** Would it still be true if the sheet, tab and cell it came from were deleted tomorrow? *NO → drop.*
- **U2** Is it a quantity someone measures, a computation someone performs, a threshold someone respects, or a policy about what is counted? *NO → drop.*
- **U3** Name the artefact it becomes, from the table below. *Cannot → drop.*
- **U4** Can it be stated without a cell, column letter, tab or file name? *NO → drop; YES → that is the statement.*
- **U5** Is it the same wherever it appears? *YES → one entry with all its bindings; NO → continue (a genuine divergence is a `split` with `template_of`).*
- **U6** Does its value change every night? *YES → not a fact (v2 QF-1).*
- **U7** Does it already have a home — a field's `description`, `unit` or `constraints.enum`; an item's `tracked[]` or `units[]`; a source or account on an existing cell; an `issues[]` entry; an `unknown` leaf? *YES → attach there, mint nothing; NO → continue.*
- **U8** If it is a note: what does it point at and what does it ask? *Names nothing or asks nothing → drop.*

**The consumer contract (U3's table).** These eight artefacts are the store's output vocabulary; §9 adds one PRD requirement and one ARD paragraph stating this, so U3 is graded against a written requirement.

| artefact | carried by | the decision writes |
|---|---|---|
| item-master row | `item` | title, category, unit, pack |
| table column with a unit | `record.fields[]` | key, unit, description |
| BOM / recipe row | reference `rows[]` | nothing (engine) |
| settings constant — a par level, a tolerance, a conversion factor, a threshold; a consumer is not required | constant rule | value or range, nature |
| validation constraint | `fields[].constraints.enum` | nothing (engine) |
| computed field | rule `expr` | expr, inputs, outputs |
| join between two tables | `fields[].refItems`, `instances[].imports[]` | refItems |
| known data defect | `issues[]` | description, when the unit found it |

`validate` enforces U4 (the lint) and U8 (`about[]`, `question`); `digest` flags U5 violations (`equal_expr`) for the reviewer rather than refusing them.

### 5.2 The style card (prompt and lint)

- **`title`**: a noun phrase naming the concept, ≤ 60 characters, Persian, no file, tab or cell names, no Latin except an item code.
- **`statement`**: one to three sentences in the register of a written procedure — what is measured or computed, in what unit, by whom, when; for a record, what it is and who fills it; for an item, what it is and how it is counted. Never: an A1 address, a column letter, a tab, file or `Table_*` name, formula text, a function name, a schema field name, the pipeline's vocabulary («پاس», «اسکلت», «بخش از داده‌ها», «واحد کاری», «بچ», «original», «bindings», «FEEL», «account», «expr»), a quotation, «گفته شد»/«گوینده».
- **Worked pair:** «ستون J تب پیتزا (گروه J6:J15): انحراف برابر است با مصرف واقعی منهای مصرف اعلامی.» → «انحراف مصرف هر مادهٔ اولیه در پایان شب برابر است با مصرف واقعی (برآوردشده از فروش و نسخهٔ غذاها) منهای مصرف اعلامی لاین. مقدار منفی یعنی لاین بیش از انتظار مصرف کرده است.»
- **Lint** (in `engine/merge_facts/content.py`, so `validate`, `apply` and `assemble` share it; on envelope `title`, `statement`, `aliases[]` and payload `fields[].description`, `grain`, `method`, `exceptions`, `tracked[].reason`, an `issues[].description` a **unit** wrote — an engine-templated one is exempt, because it must name the columns that went missing — and the values of `applies_to[].params` that reach `gate-b.md`): reject a reference token (`'sheet'!` optional, `$?[A-Z]{1,3}$?(N|\d{1,5})`, optionally ranged, with the §2.3(d) guards); `\.xlsx\b`, `\.gs\b`, `Table_`, `IMPORT_FROM_SHEET`, `\bLET\(`, `LAMBDA`; the pipeline words above; any Latin token of four or more letters except `csv`, `Excel`, `sheet`, a symbol in the exemption list (`unit_symbols[]`), and an item code; a «…» span of more than eight words; the colloquial endings «می‌زنن», «می‌کنن», «داشته باشن», «بگیم», «می‌گیم». «ستون», «تب», «سلول» are allowed only in a record's own `statement` and a field's `description`. `reason`, `assembly.json` and engine-minted stub titles are not linted.

### 5.3 The classification decision table (replaces v2 §8's ladder in the prompt)

The table answers only what U3's table does not — which **kind** a passing candidate takes.

| the candidate is | kind | payload |
|---|---|---|
| one input split into several outputs with shares | rule | `outputs[].share` |
| varies by condition | rule `lang: table` | `table` |
| a policy with no formula | rule `lang: text` | its threshold as a separate constant, `null` if unstated |
| a colour rule with a business threshold (not a sign test at 0) | one constant rule | `nature: limit` |
| has inputs, produces an output, is bound to a formula | rule | `expr` in FEEL stating the **business** computation (an aggregate over the BOM for actual consumption), or `lang: table`; `original` alone is not a legal state — `expr_missing` is counted at Gate B and reported by `audit` |
| a value stated singly with business meaning | constant rule, or the item's `units[]`/`pack` when it is a pack size | `value` or `range` |
| a value that is a formula's literal | a parameter of the rule that reads it (`applies_to[].params`) | — |
| who captures what, when, into which field | measurement | `quantity` is the **kind** of quantity, never a number |
| a staff-written gap | an `unknown` leaf on the entry it concerns | — |
| none of the above, and it points at an entry and asks something | note | `about[]`, `question` |

## 6. Runtime and coordinator rules (playbook v3)

- Batches of at most four `Task`s per message; await the batch; validate each unit; the next batch rides in the next message with a progress line («۸ از ۲۶ بخش از داده‌ها بررسی شد»). Never more than four in one message (ADR 0011).
- **Yield rule.** The timer is the trigger the pipeline owns: `facts-plan status` prints `elapsed_s` since `turn.json` and `yield: true` above 2,400 s, and it is the only signal the coordinator acts on; the coordinator checks it after Stage 1, Stage 2 and Stage P, between batches and before Stage R, and on `yield: true` sends the progress line («۸ از ۲۶ بخش بررسی شد؛ برای ادامه «ادامه بده» را بفرستید») as the last message of the turn, and Stage 0 resumes. The bridge's budget warning, when the run is on the bot and one arrives in the conversation, is treated as a `yield: true` at the next boundary; on the laptop path (§6.1) no such warning exists and the timer is the whole rule. Ending a turn at a boundary is a normal, lossless outcome; a run larger than one turn's cap simply spans two turns.
- The coordinator reads `facts-plan status` output (a compact table of `unit · type · state · attempts`), `gate-b.md`, `report.md` and validator output — never `plan.json`, `skeleton.json`, a unit's output, `assembly.json` or the delta.
- A precondition failure at Stage 5 is reported and the run stops (QF-54). No hand edits, ever.
- Resume ladder (`facts-plan status`): no `skeleton.json` → Stage P (or earlier, by artefact presence: transcripts → dumps → skeleton); pending units → Stage U; all done, no delta → Stage R; delta present, `id-map.json` absent → Gate B (a retry of `apply` is safe); `id-map.json` present, run not finished → Stage 6.
- The manifest agent is dispatched only for rows holding `unresolved`; a correction to a mechanical column is applied by the playbook without a dispatch.
- Owner-facing vocabulary: «بخش از داده‌ها» for a unit, «فایل» for a workbook, the workbook's title for its name; never «واحد کاری», a unit id, a stage letter or a code.

### 6.1 The laptop dev path

Before any facts run in a Claude Code terminal: (a) `export CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` — otherwise a unit longer than two minutes may be backgrounded, the failure ADR 0006 removed for the bot; (b) remove `~/.claude/.ponytail-active` (or `export PONYTAIL_DEFAULT_MODE=off`) — the plugin's `SubagentStart` hook injects a coding-minimality persona into every subagent when the mode flag is present, and `PONYTAIL_SUBAGENT_MATCHER` is an opt-in allowlist that fails open, so it must not be used for this; the playbook's Stage U precondition is `test -f ~/.claude/.ponytail-active` failing; (c) the playbook uses only `Read, Write, Edit, Bash, Glob, Grep, Task` — the bot's allowlist — so nothing authored on the laptop breaks on the server; (d) every dispatch carries the no-background sentence, and the coordinator never emits a prose-only «waiting» message. Recorded in runbook 07 as a pre-run checklist; the local test-bot container is checked for `/root/.claude/.ponytail-active` before the §8 run.

## 10. Deliberate ceilings (v2 §18 additions)

- One review round on the assembled result, capped at 60 decisions and 20 rewrites; a review whose digest hash no longer matches, that addresses an entry ambiguously, or that fails validation twice is discarded and reported. A Stage V repair re-enters Stage R once.
- The review digest is capped at 50 K tokens; above it the run proceeds without the review and says so.
- Template detection is tab-name plus code-list equality or non-empty subset; a tab whose header drifted between branches becomes two templates, flagged for the reviewer.
- A rule candidate is keyed by its output header; two unrelated columns that share a header in one department land in one candidate and the unit splits them.
- No semantic de-duplication of transcript facts beyond key, title and `expr` equality plus the reviewer; the audit's look-alike report remains the backstop.
- One `apply` per run; no lock; no per-unit apply.
- `applies_to[]`/`instances[]`/`imports[]` members are never removed automatically; `audit` reports stale ones; removal is an `edit-fact` decision.
- An `imports[].source` may stay a locator indefinitely when the source department never runs; every reader accepts both forms.
- Item candidates come from codes; an uncoded column becomes an item only through a unit's `new`.
- The process-index slice is a keyword filter; an anchor it missed is added at the next run or through `edit-fact`.
- Cost and wall-clock are bounded per turn, not per run; a department larger than cooking spans turns.
- Each run still commits a full `facts-before/` snapshot; at nine departments and ~2,000 entries that is ~1.5 M committed lines. Accepted for v3; a per-entry diff is the upgrade.
- `facts/originals/` is keyed by entry id, not content; two entries with one body store it twice.
- Workbook stubs for a Drive id with no manifest row (v2 QF-20 case 2) stay as v2, scoped per §3.2.
- Gate M still surfaces every **new** row estate-wide, because the department of a new workbook is what the owner's answer establishes; the estate gains a workbook a few times a year.
- `row_labels` are captured only for tabs under 60 rows; a larger tab's rows are identified through its reference rows or not at all.
